# 音声の作り方

評価とデモで使う文字起こしを作るために、ダミー面談の台本を ElevenLabs で音声にする手順です。できた音声はボイスメモで文字起こしします。

## まとめ

- 台本（1 行 1 発話・「話者名：本文」）を `npm run tts -- <台本ファイル>` に渡すと MP3 ができます。Mac では、ボイスメモに入れるための M4A もできます。
- 声は `scripts/tts/voices.json` で話者名ごとに決めます。API キーは環境変数 `ELEVENLABS_API_KEY` から読みます。
- 最初に `--dry-run` を付けて回し、台本の読み取りと分け方を確かめます。API は呼ばれません。

```bash
npm run tts -- scripts/tts/sample.txt --dry-run
```

## 用意するもの

- Node.js 22.18 以上。`.mts` のファイルを、ビルドせずにそのまま実行するためです。`node --version` で確かめてください。足す依存の部品はありません。
- ElevenLabs の API キー。Text to Dialogue API を使えるものが要ります。
- 使う声の ID。ElevenLabs の画面で控えてください。

## 1. 声を決める

`scripts/tts/voices.json` の `speakers` に、台本の話者名ごとの声の ID を書きます。`voiceName` は自分用の覚え書きで、API には送りません。

```json
{
  "models": ["eleven_v4", "eleven_v3"],
  "outputFormat": "mp3_44100_128",
  "maxCharsPerRequest": 2000,
  "speakers": {
    "講師": { "voiceName": "Hajisan", "voiceId": "ここに声の ID" },
    "生徒": { "voiceName": "Sky", "voiceId": "ここに声の ID" },
    "保護者": { "voiceName": "", "voiceId": "" },
    "コーチ": { "voiceName": "", "voiceId": "" },
    "クライアント": { "voiceName": "", "voiceId": "" }
  }
}
```

| 項目 | 意味 |
|---|---|
| `models` | 試す順に並べたモデル ID。最初のモデルが使えなければ、次のモデルを使う（「4. 音声を作る」） |
| `outputFormat` | ElevenLabs の `output_format`。分けて作った MP3 をつなぐので、`mp3_` で始まる値だけにする |
| `maxCharsPerRequest` | 1 回の呼び出しで送る本文の文字数の上限。ElevenLabs は Text to Dialogue に送る文字数を合わせて 2,000 字以内にするよう勧めている。長い台本はこの字数で分けて送る |
| `speakers` | 話者名ごとの声。`voiceId` が空の話者が台本に出てくると、音声は作らずに止まる。台本に出てこない話者は空のままでよい |
| `languageCode`（任意） | 書いたときだけ `language_code` として送る（例 `"ja"`）。そのモデルが対応していないと API がエラーを返す |
| `seed`（任意） | 書いたときだけ送る。同じ値にすると、似た読み方になりやすい |
| `stability`（任意） | 書いたときだけ `settings.stability` として送る（0〜1）。低いほど表現の幅が広く、高いほど落ち着く |

- 話者名は「講師／生徒」「講師／保護者」「コーチ／クライアント」を使います。台本の話者名と `speakers` の名前は同じ文字にします。
- 声の ID は、voices.json に書いてコミットしてかまいません。ID だけでは声を使えないからです。API キーは voices.json にも、どのファイルにも書きません。
- 別の設定を使うときは `--config <ファイル>` で渡します。

## 2. 台本を書く

```text
# 動作確認用の短いダミー台本（実在の人物ではありません）
講師：じゃあ、始めようか。先週の小テスト、自分ではどうだった？
生徒：[hesitates] うーん……計算は合ってたんですけど、文章題が時間切れで。
講師：時間切れか。どの問題で止まったか、覚えてる？
```

- 1 行に 1 発話を「話者名：本文」の形で書きます。区切りは全角の「：」です。半角の「:」でも読めます。区切りに使うのは行の最初のコロンだけなので、本文の中のコロン（「3:00」など）はそのまま残ります。
- `[hesitates]`・`[sighs]`・`[laughs]` のような英語の角括弧は、演技の指示としてそのまま API に送ります。指示がどれだけ効くかはモデルによります。
- 空行と `#` で始まる行は読み飛ばします。台本の見出しや覚え書きに使えます。
- 1 発話だけで `maxCharsPerRequest` を超える行があると止まります。その行を 2 行以上に分けてください（同じ話者名を続けてかまいません）。
- 台本はダミーだけにします。実在の生徒・保護者・講師・顧客の名前は入れません。

動作確認用の短い台本が `scripts/tts/sample.txt` にあります。

## 3. 分け方を確かめる（API を呼ばない）

```bash
npm run tts -- scripts/tts/sample.txt --dry-run
```

台本の読み取り、話者ごとの発話の数、何回に分けて送るか、それぞれの回の行の範囲と文字数、声の設定が出ます。API キーは要りません。声の ID が空でも止まらず、「未設定」と出ます。

長い台本の分け方はこうなります。

- 分けるのは発話の切れ目だけです。発話の途中では切りません。発話の順番も変えません。
- 1 回に送るのは、本文 `maxCharsPerRequest` 字まで、声 10 種類までです（Text to Dialogue の 1 回の上限）。
- 回数はできるだけ少なくします。そのうえで、1 回あたりの文字数がそろうように分けます。最後の回だけが短く残ると、そこだけ前後の流れが薄くなるためです。

## 4. 音声を作る

API キーを環境変数に入れます。1 つ目のコマンドのあとでキーを貼って Enter を押します。こうして入れると、キーは画面にもシェルの履歴にも残りません。

```bash
read -rs ELEVENLABS_API_KEY
```

```bash
export ELEVENLABS_API_KEY
```

そのまま回します。

```bash
npm run tts -- scripts/tts/sample.txt
```

- できた MP3 は、台本と同じ場所に同じ名前で置かれます（`sample.txt` なら `sample.mp3`）。置き場所は `--out <ファイル名.mp3>` で変えられます。パスは、コマンドを打った場所から読みます。
- Mac では、続けて `afconvert -f m4af -d aac` で同じ名前の M4A を作ります。変換しないときは `--no-m4a` を付けます。Mac 以外では M4A は作りません。
- 作った MP3・M4A は `.gitignore` に入れてあるので、コミットされません。台本から作り直せます。
- キーをすでに自分で `.env.local` などのファイルに置いているなら、Node に読ませる方法もあります：`node --env-file=.env.local scripts/tts/make-audio.mts <台本ファイル>`

### モデル

- `models` の先頭（Eleven v4、`eleven_v4`）を先に試します。1 回目の呼び出しを API が断ったとき（400・403・404・422）は、理由を表示して、次のモデル（Eleven v3、`eleven_v3`）で 1 回目から作り直します。
- 1 本の音声の中で、モデルは混ぜません。2 回目以降に失敗したときは、モデルを切り替えずに止まります。
- `--model <モデル ID>` を付けると、そのモデルだけを使います。

### 途中で失敗したとき

- 429（混んでいる・量の上限）、5xx、つながらないときは、2 秒・4 秒・8 秒と待って 3 回までやり直します。
- それでも失敗したら止まります。作り終えた分は `<出力名>.parts/` に残ります（`sample.mp3` なら `sample.parts/`）。同じコマンドをもう一度回すと、残っている分は使い、足りない分だけを送ります。送る中身（本文・声・モデル・出力の形）が変わった回は作り直します。
- 全部できたら、MP3 を 1 本につないで、`.parts/` は消します。そのあと同じコマンドを回すと、最初から作り直します。新しい読み方の音声になり、そのぶんの利用量も使います。

### つなぎ方

分けて作った MP3 は、フレームを順に並べて 1 本にします。並べる前に、各ファイルのタグ（ID3）と、ファイルごとの長さを書いた先頭のヘッダー（Xing／Info）を外します。外さないと、再生時間を読み違えることがあるためです。つなぎ目に、ごく短い無音が入ることがあります。

## 5. ボイスメモで文字起こしする

できた M4A をボイスメモに入れて、文字起こしします。文字起こしの文は、話者の無い文のまま画面 1 に貼るか、評価のケースにします。

## オプション

| オプション | 意味 |
|---|---|
| `--dry-run` | API を呼ばずに、台本の読み取りと分け方だけを見せる |
| `-o`, `--out <path>` | 出力する MP3。既定は台本と同じ場所・同じ名前の `.mp3` |
| `-c`, `--config <path>` | 声の設定。既定は `scripts/tts/voices.json` |
| `-m`, `--model <id>` | このモデルだけを使う |
| `--no-m4a` | Mac でも M4A に変換しない |
| `-h`, `--help` | 使い方を出す |

`npm run` を通さずに、`node scripts/tts/make-audio.mts <台本ファイル> [オプション]` でも回せます。

## テスト

```bash
node --test "scripts/tts/*.test.mts"
```

API は呼びません。テストで確かめていることは次のとおりです。

- 台本の読み取り：形の合わない行は行番号を添えて知らせる。演技の指示はそのまま残す
- 分け方：上限を守る。発話の途中で切らない。順番を変えない。回数はいちばん少なくする
- 声の設定の確かめ
- MP3 のつなぎ方：タグとヘッダーを外し、音声のフレームは残す
- API に送る中身、モデルの切り替え、やり直し、途中からの再開：`fetch` を差し替えて確かめる

## 確かめていないこと

次の 3 つは、Mac で本物の API を呼んで確かめます。

- 本物の API を呼ぶこと。スクリプトを作った環境からは ElevenLabs にもつながらず、テストでは `fetch` を差し替えている。
- `eleven_v4` が Text to Dialogue で使えること。ElevenLabs のモデル一覧には使えると書いてあるが、呼んで確かめてはいない。使えなければ `eleven_v3` に切り替わる。
- 1 回 2,000 字という上限。ElevenLabs が勧める値で、硬い上限ではない。途中で音声が切れたり、文字数のエラーが返ったりしたら、`maxCharsPerRequest` を下げる。
