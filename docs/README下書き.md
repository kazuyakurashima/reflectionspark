## 問題

面談（生徒面談・保護者面談・1on1）は、終わった直後に「うまくいった」と感じやすい一方で、言いにくいことを言わなかったこと、相手が自分で決めるまで待たなかったことには、本人が気づきにくい。録音を聞き直す時間はなく、上司が毎回同席することもない。振り返りは「反省の言葉」で終わり、次の面談で何を変えるかが決まらないまま、同じ形の面談が続く。

## なぜ今

- iPhone や Mac のボイスメモで、面談がそのまま文字になるようになった。話者ラベルの無い文でも、AI が発話に区切って話者を付けられる。
- 長い文脈を読み、発話の単位で引用を返し、引用が原文と一致するかをプログラムで確かめられる AI が使えるようになった（Claude の citations）。
- AI の助言は「もうやっていること」を指しやすく、引用が必須でも原文と合わないことがある、と分かってきた。だから、根拠を検証し、人を採点せず、本人の答えから行動を作る設計が要る。

## Claude がどう解くか

一本の流れは 5 つの画面です。

| # | 画面 | 本人がすること | Claude とアプリがすること |
|---|---|---|---|
| 1 | 面談内容を入力する | 文字起こしを貼る。Claude が付けた話者を確かめて直す | 発話に区切り、講師と相手を付け、聞き違いを直す箇所と意味が通らない箇所を挙げる。元の文は残す |
| 2 | フィードバックを読む | 先に自分の点と一言を付ける（AI に渡さない）。そのあと読む | 場面 2 つ（よく表れた所・次に試せる所）を引用つきで、問い 2〜3、項目ごとの点と合計、倫理チェックの 1 行 |
| 3 | 自分の言葉で | 問いに答えを書く | 待つ |
| 4 | 次に試すひとつ（Your Spark） | 候補 2〜3 から選ぶ、直す、見送る | 「もし（場面）なら、（行動）する」の候補、セリフの例、できたかの基準 |
| 5 | 次の面談で | 続きの面談を貼る。先に「できた／一部／まだ／場面がなかった」と自分の点を付ける | 自己評価を見ずに読み、判定・根拠の引用・なぜの一文・項目ごとの点 |

Claude の使い方：

- **引用は検証したものだけ。** 文字起こしを 1 発話 1 ブロックの document として渡し、citations で返ってきた `cited_text` を発話の原文と完全一致で照合する。一致しない引用は画面に出さない。「引用 n 件すべて原文と一致」をバッジで出す。
- **引用が要る工程と、形の決まった出力が要る工程を分ける。** citations と構造化出力は同じ呼び出しで使えないので、場面・読み・問い（工程 1）は citations、点（工程 2）と行動の候補（工程 3）は構造化出力で呼ぶ。
- **整形は 3 つの呼び出しに分ける。** 区切りと話者、直す箇所の一覧、意味が通らない箇所。別の仕事を一つの呼び出しに混ぜると、言った言葉まで書き換えてしまう。
- **覚えている。** 分析の結果（場面と行動だけ。文字起こしの全文は渡さない）を Managed Agents の記録係がメモリストアに書き、整理は夢で行う。人の性質の言葉では書かず、本人が読めて直せる。
- モデルは分析が Claude Opus 5.5（adaptive thinking、streaming）、夢は Sonnet 5.5 から始める。

## どこが新しいか

1. **人を採点しない。** 点は面談の点で、人の点ではない。本人が先に自分の点を付け、AI の点は引用と問いの後に置く。合計はアプリが計算する。
2. **根拠は原文の引用だけ。** 言い換えた引用は捨てる。読みは「ここで何が起きたか」として引用と分け、「〜と読める」と書く。
3. **場面では問いで返し、行動は一つに絞る。** 候補は本人の答えから作り、本人が選ぶ・直す・見送る。「もし（場面）なら、（行動）する」。
4. **次回に戻ってくる。** 前回決めた行動が次の面談でどう現れたかを、引用つきで確かめる。本人の自己評価を先に取り、AI はそれを見ずに読む。
5. **面談する側を覚えている。** 覚えるのは場面と行動と結果。相手のタイプ分けはしない。
6. **整形を本人が確かめる。** 話者の確からしさが低い発話と、直した所を先に出し、元の文を添える。0 件でも「聞き違いが無いことの証明ではない」と添える。

## 試し方

### Demo Mode（実データ不要）

公開 URL を開き、画面 1 で「サンプルを選ぶ（Demo Mode）」を押す。整形 → 確かめる → 自分の点を付けて読む → 問いに答える → 次に試すひとつを選ぶ → 画面 5 で「サンプルの続きを選ぶ」→ 自己評価を付けて追跡を読む、まで 3 分。サンプルは作ったダミーの 1 組（生徒面談とその続き）で、実在の人物ではありません。

### 手元で動かす

```bash
npm install
```

```bash
npm run dev
```

- `ANTHROPIC_API_KEY` を環境変数に入れると本物の分析が動きます。無いときは、同じ形の仮の出力で画面の流れだけを確かめられます（画面に「仮の出力」と出ます）。
- 何を API に送るか：整形後の発話の並び、採点表の考え方、前回の「次に試すひとつ」。本人の自己採点・自己評価・一言は送りません。
- どこに保存するか：ブラウザの localStorage（面談 1 件分）。記録係とメモリストアは今後。
- 個人情報を入れない。実在の生徒・保護者・講師・顧客の名前や本物の面談の文字起こしは使わない。

### 評価を回す

```bash
npm test
```

```bash
node eval/scripts/run-cases.mts
```

```bash
node eval/scripts/report.mts --judge
```

- 正解：`eval/正解.md`（v1）と `eval/truth/*.json`。
- 対応付け（ボイスメモと台本の行）：`node eval/scripts/align-cases.mts`。
- 結果：`eval/results/runs/report.md`（1 行 1 ケースの表）。
- 整形（工程 0a）の速さの比べ：`node eval/scripts/step0-speed.mts student-shinro student-shinro-2`（作り方 copy／label × モデル × 考える量。`docs/整形の速い作り方.md`）。
