## 問題

面談（生徒面談・保護者面談・1on1）は、終わった直後に「うまくいった」と感じやすい一方で、言いにくいことを言わなかったこと、相手が自分で決めるまで待たなかったことには、本人が気づきにくい。録音を聞き直す時間はなく、上司が毎回同席することもない。振り返りは「反省の言葉」で終わり、次の面談で何を変えるかが決まらないまま、同じ形の面談が続く。

## なぜ今

- iPhone や Mac のボイスメモで、面談がそのまま文字になるようになった。話者ラベルの無い文でも、AI が発話に区切って話者を付けられる。
- 長い文脈を読み、発話の単位で引用を返し、引用が原文と一致するかをプログラムで確かめられる AI が使えるようになった（Claude の citations）。
- AI の助言は「もうやっていること」を指しやすく、引用を必須にしても原文と合わないことがある、と分かってきた。だから、根拠を検証し、人を採点せず、本人の答えから行動を作る設計が要る。

## Claude がどう解くか

一本の流れは 5 つの画面です（画面の見出しと同じ）。

| # | 画面 | 本人がすること | Claude とアプリがすること |
|---|---|---|---|
| 1 | 面談内容を入力する | 文字起こしを貼る（話者の無いボイスメモの文でよい）。場面の種類（生徒面談／保護者面談／コーチング）を選び、相手の呼び名を入れる。付いた話者と直した所を確かめて直す | 発話に区切って講師と相手を付け（0a）、聞き違いを直す箇所を挙げ（0b）、意味が通らない箇所の推測を別に添える（0c）。元の文は残す。話者と区切りで迷った所と推測を付けた所を一つずつ、Claude が直した所を一覧で先に出し、全文は畳んで後ろに置く |
| 2 | フィードバックを読む | 先に自分の点（10 点満点）と一言を付ける（AI に渡さない）。そのあと読む | 場面 2 つ（よく表れた所・次に試せる所）を、原文のやりとり（直前・照合済みの引用・直後）→ 文字起こしから確かめられること（観察・直後の相手の反応）→ AI の読み（最初は閉じている）→ 問いの順で。問い 2〜3、項目ごとの点（1〜5、仮）か「判定しない」、アプリが計算した合計（10 点に換算）、気づきの持ち主、数えた記録、倫理チェックの 1 行 |
| 3 | 自分の言葉で | 問いに答えを書く（AI の読みと違う考えもそのまま書く） | 待つ（AI を呼ばない） |
| 4 | 次に試すひとつ（Your Spark） | 候補 2〜3 から「これにする」「直して使う」「今回は見送る」 | 「もし（場面）なら、（行動）する」の候補。押すとセリフの例と、できたかの基準が開く |
| 5 | 次の面談で | 続きの面談を貼って整形し、先に「できた／一部／まだ／場面がなかった」と自分の点を付ける | 自己評価を見ずに読み、判定・根拠の引用・なぜの一文・項目ごとの点。本人と AI の判定を並べ、ずれは確かめる点として出す。同じ行動を追うのが 3 回目なら、続けるか変えるかを聞く |

Claude の使い方（コードで確かめられること）：

- **引用は検証したものだけ**（`engine/citations.mts`）。文字起こしは 1 発話 1 ブロックの document（`source.type: "content"`、各ブロックは「〔発話 n〕話者：本文」）にして citations を有効にし、返ってきた `cited_text` が、該当するブロックの文をつないだものと完全一致したときだけ画面に出す。一字でも違えば捨てる。発話番号は `start_block_index` をそのまま使い、先頭の札「〔発話 n〕」も同じ番号にして、AI に発話を数えさせない（`engine/utterance-no.mts`。AI が文の中に書いた番号は、範囲の中の整数だけを受け取る）。画面の引用には「引用は原文と一致」と添え、生成した数・捨てた数・引用を出せなかった場面の数は記録に残す。モデルが本文に「」で書いた言葉は検証していないので、文字起こしに無ければ「」を外して出す（`engine/guard.mts`）。
- **引用が要る工程と、形の決まった出力が要る工程を分ける**（`engine/claude.mts`）。citations と構造化出力（`output_config.format`）は同じ呼び出しで使えない（400）。場面・読み・問い（工程 1）と追跡（工程 4）は citations 付きの呼び出し、整形（工程 0a・0b・0c）、点（工程 2）、行動の候補（工程 3）は JSON Schema の構造化出力で呼ぶ。
- **整形は 3 つの呼び出しに分ける**（`engine/step0.mts`）。0a は区切りと話者と確からしさを返し、モデルが写した本文は元の文字起こしに当て直す（言葉を変えない。当て直せない所は「区切りが分からない所」として残し、本人が分ける）。0a には 2 つの作り方があり、`copy`（既定。モデルに本文を写させて当て直す）と `label`（アプリが文に切って番号を付け、モデルは番号ごとの話者だけを返す）を環境変数で切り替える（`docs/整形の速い作り方.md`）。0b は直す箇所の一覧だけを返し、直す前の文字列がその発話にちょうど 1 か所あるものだけ当て、捨てた直しは理由を残す。0c は整形とも分析とも別に送り、推測は画面で元の文と並べて見せる。本人が「この推測で直す」を押したときだけ本文に入り、押さなければ分析には渡らない。0c が失敗しても分析は止めない。
- **先に入った評価を渡さない**（`app/api/*/route.ts`。設計書の決まり 10）。分析・候補・追跡の Route Handler は、本人の自己採点・一言・自己評価、前回の AI の点と判定を受け取らず、入っていれば 400 を返す。追跡のプロンプトにも「本人の自己評価は渡されていません」と書いてある。
- **点は最後に、合計はアプリが**（`engine/rubric.mts`）。工程 1 のプロンプトには点を書かせず（テストで守る）、点は工程 2 の別の呼び出しで項目ごとに出す。合計は判定した項目だけを分母にして 10 点に換算し、「判定しない」は 0 点にしない。尺度（1〜5）と配点は初版の仮で、画面にもそう書く。
- **人物の性質を言い表す言葉を検査する**（`engine/forbidden-words.mts`、`engine/guard.mts`）。AI の出力は欄ごとに検査し、当たった欄は「表示を控えました」に差し替えて元の文を記録に残す。画面の文言も同じ一覧で検査する（`app/ui-words.test.mts`）。
- **モデルと呼び方**：既定はすべての工程が `claude-opus-5-5`（環境変数で変えられる。0a だけ別のモデルも指定できる）。adaptive thinking で、effort は 0a が low（11/5 に medium から変えた）、0b・0c が medium、分析が high。system と document にプロンプトキャッシュを付ける。工程 1・4 は streaming で受け取り、最初の引用が届くまでの時間を記録するが、画面には工程 1 と 2 がそろってから出す（画面への streaming は今後）。

## どこが新しいか

1. **人を採点しない。** 点は面談の点で、人の点ではない。本人が先に自分の点を付け、AI の点は引用と問いの後に置く。合計はアプリが計算し、「判定しない」を 0 点にしない。
2. **根拠は原文の引用だけ。** 言い換えた引用は捨て、AI が本文に書いた「」も文字起こしに無ければ外す。場面の中は、原文のやりとり（直前・引用・直後）→ 文字起こしから確かめられること（観察・直後の相手の反応）→ AI の読み（「〜と読める」）→ 問いの順で、AI の読みは最初は閉じておき、本人が自分の読みを持ってから開く。「引用は原文と一致」は引用が文字起こしのとおりである印で、AI の読みが合っている印ではないと画面に書く。
3. **場面では問いで返し、行動は一つに絞る。** 問いは場面ごとに一つで、うち一つは行動につながる問い。候補は本人の答えから作り、言葉に表れない行動は落とし、本人が選ぶ・直す・見送る。「もし（場面）なら、（行動）する」。
4. **次回に戻ってくる。** 前回決めた行動が次の面談でどう現れたかを、引用つきで確かめる。本人の自己評価を先に取り、AI はそれを見ずに読む。並べて、ずれは「確かめる点」として出す。
5. **整形を本人が確かめる。** 区切りが分からない所、話者を確かめる所、相手が 2 人以上かもしれない所、意味が通らない所を一つずつ先に出し、Claude が聞き違いを直した所は同じ直しを 1 行にまとめた一覧で見せる。直す前と直した後を並べ、元の文はいつも残す。モデルが写し間違えた本文は元の文に当て直す。0 件でも「聞き違いが無いことの証明ではない」と添える。
6. **（今後）面談する側を覚えている。** 覚えるのは場面と行動と結果で、人物の性質の言葉では書かず、相手を分類しない。記録係と夢はまだ無い（上の「今後」）。

## 試し方

### Demo Mode（実データ不要）

公開 URL を開きます（手元なら `npm run dev` のあと http://localhost:3000）。

1. 画面 1「面談内容を入力する」で「サンプルを選ぶ（Demo Mode）」を押す。文字起こしの欄に、ダミーの生徒面談（話者の無いボイスメモの文）が入る。「整形する（発話に区切って話者を付ける）」を押す（1 分前後かかることがあり、待つ間は経過の秒が出る）。「確かめる所」（話者・区切り・推測）と「Claude が直した所」の一覧を見て、「確かめた。フィードバックを読む →」。
2. 画面 2「フィードバックを読む」で、自分の点（10 点満点）と一言を入れて「付けた。読む」。ひと目で → サマリー → 面談の流れ → よく表れた所 → 次に試せる所 → 問い → 項目ごとの点と合計 → 気づきの持ち主 → 数えた記録 → 倫理チェックの順に読む。場面の中では、原文のやりとりと確かめられることを先に読み、「AI の読みを開く」で読みを開く。「次へ：3. 自分の言葉で →」。
3. 画面 3「自分の言葉で」で問いに答えを書く（全部に答えなくてよい）。「次へ：次に試すひとつ →」。
4. 画面 4「次に試すひとつ」で候補を読み、「これにする」か「直して使う」か「今回は見送る（持ち帰らない）」。「次へ：次の面談で →」。
5. 画面 5「次の面談で」で「サンプルの続きを選ぶ（Demo Mode）」を押し、「整形する」。自分で「できた／一部／まだ／場面がなかった」と点を選んで「付けた。AI の判定を見る」。AI の判定・根拠の引用・なぜの一文・項目ごとの点が開く。

- サンプルは作ったダミーの 1 組（生徒面談とその続き）で、実在の人物ではありません。
- Demo Mode でも、整形と分析は本物の Claude を呼びます（サーバーに `ANTHROPIC_API_KEY` があるとき）。無いときは同じ形の仮の出力になり、画面にそう出ます。

| 名前 | 何に効くか | 既定 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude を呼ぶ鍵。サーバー側（Route Handler と評価スクリプト）だけが読む。無いと Route Handler は仮の出力（`engine/mock.mts`）を返し、API を呼ぶ評価スクリプトは止まる | 無し |
| `REFLECTIONSPARK_MODEL` | 分析と整形のモデル（工程 0b・0c・1・2・3・4。0a も、`REFLECTIONSPARK_STEP0_MODEL` が空ならこれ） | `claude-opus-5-5` |
| `REFLECTIONSPARK_STEP0_MODE` | 工程 0a の作り方。`copy`（モデルに本文を写させて元の文に当て直す）か `label`（アプリが文に切り、モデルは番号ごとの話者だけを返す）。`docs/整形の速い作り方.md` | `copy` |
| `REFLECTIONSPARK_STEP0_MODEL` | 工程 0a だけのモデル | `REFLECTIONSPARK_MODEL` と同じ |
| `REFLECTIONSPARK_STEP0_EFFORT` | 工程 0a の考える量（`low`・`medium`・`high`・`xhigh`・`max`）。値が読めなければ起動時に止まる | `low` |
| `REFLECTIONSPARK_JUDGE_MODEL` | 評価の LLM 判定のモデル（軸 3・4・10 と、軸 12 の推測の意味） | `claude-opus-5-5` |
| `ELEVENLABS_API_KEY` | 評価の音声づくり（`npm run tts`）だけ。アプリは読まない | 無し |
| `NODE_OPTIONS` | Node 22.6〜22.17 で `.mts` を動かすときに `--experimental-strip-types --no-warnings` を入れる。22.18 以上では要らない | 無し |

何を API に送るか（各工程の先頭に「受け取る／渡さない」を書いてある。`engine/step0.mts`〜`step4.mts`）：

- 送る：貼った文字起こし（整形へ。4 万字まで）、整形後の発話の並び（話者と本文）、場面の種類、採点表の考え方、工程 1 の場面（工程 2 へ）、「次に試せる所」の場面と本人の問いへの答え（工程 3 へ）、前回の「次に試すひとつ」とできたかの基準と前回の場面の文（工程 4 へ）。
- 送らない：本人の自己採点・一言・自己評価、前回の AI の点と判定、相手の呼び名、工程 0c の推測。
- どこに保存するか：このブラウザの localStorage（面談 1 件分。整形の結果、自分の点と一言、答え、候補、選んだ行動、追跡）。サーバーには保存しない（Route Handler は結果を返すだけ）。評価スクリプトの出力は `eval/results/` の下。
- 個人情報を入れない。実在の生徒・保護者・講師・顧客の名前や本物の面談の文字起こしは使わない。

- `npm test`：API を呼ばない。引用の照合、人物の性質の言葉の検出、整形の当て方、軸の計算、画面の文言などの単体テスト。
- `eval:align`：ボイスメモの文字起こしと台本の行の対応を 12 本で作る（API を呼ばない）。出力は `eval/results/align/`。
- `eval:run`：正解のある本を回す（工程 0・1・2。続きの面談は工程 4 も）。整形は 1 本 1 回だけ回して保存し、使い回す。`-- --fresh` で回し直し、`-- --stability <case> <回数>` で整形の揺れ、`-- --dry-run` で API を呼ばずに入力と保存先を確かめる。出力は `eval/results/runs/<case>/`。
- `eval:report`：保存した出力から軸の数字を計算し、`eval/results/runs/report.md` に 1 行 1 ケースの表を書く。`--judge` を付けると LLM 判定（軸 3・4・10 と、軸 12 の推測の意味）も回す。付けなければ API を呼ばない。
- `eval:e2e`：山場の 2 本で、工程 0 から 4 まで画面なしで通し、工程ごとの時間と最初の引用までの時間を測る。軸 4 はこの出力から判定する。
- `eval:step0-speed`：工程 0a の速さを比べる（作り方 copy／label × モデル × 考える量の組で順に回し、時間・出力トークン・軸 11 を 1 行 1 組の表にする。API を呼ぶ）。出力は `eval/results/step0-speed/`。考え方と決めたことは `docs/整形の速い作り方.md`。
- 正解：`eval/正解.md`（v1）と `eval/truth/*.json`。版は `eval/lib/version.mts`。
- 評価の音声づくり：`npm run tts -- <台本ファイル>`。手順は `docs/音声の作り方.md`。
