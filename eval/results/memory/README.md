## 回し方

```
node scripts/memory/run.mts analyze
node scripts/memory/run.mts record  --state <リポジトリの外のファイル> --session-cap-minor <セッション 1 本の上限>
node scripts/memory/run.mts dream   --state <同じファイル> --cap <入力トークン換算の上限>
node scripts/memory/run.mts verify  --state <同じファイル>
node scripts/memory/run.mts summary --state <同じファイル>
```

`record --dry-run` は API を呼ばず、記録の文だけを作る。Node 22 では `--experimental-strip-types` を付ける。

## 記録の形と、決めたこと

- 記録は「事実」と「その回の AI の読み（仮説）」に分けた。
  - 事実：照合済みの引用（発話番号・話者つき）、アプリが発話番号から取った前後の発話、AI が書いた観察と直後の相手の反応、決めた行動、追跡の AI の判定と根拠の引用。
  - その回の AI の読み（仮説）：読み、意図した選択として見たとき、追跡のなぜの一文、項目ごとの点。
- **読みを記録に入れた理由**：設計書は記録係に点と判定も渡すと決めていて、読みが無いと、引用だけではその場面がなぜ取り上げられたかが夢に伝わらない。ただし事実と混ぜず、見出しを分け、「事実ではない。あとの面談の事実で直すことも保留にすることもある」と書き、夢への指示でも「そのまま強めない」と決めた。読みを外した記録も同じ関数で作れる（`renderRecord(record, { includeAiReading: false })`）。外したときに夢の出力がどう変わるかは、まだ比べていない。
- 回をまたいだ変化は記録に書かない。記録係は索引に 1 行足すだけ。
