# ReflectionSpark

**面談する側（講師・コーチ）が、自分の発言を根拠に振り返り、次の一回で試す「一つの行動」を決め、次の面談でその行動がどう現れたかを確かめる AI パートナー。**

AI は人を採点しません。面談の文字起こしから、本人の発言を原文のまま引用して場面を示し、問いで返します。気づくのは本人です。

- **Demo（ログイン不要・実データ不要）**：https://reflectionspark.vercel.app
  画面 1 の「サンプルを選ぶ（Demo Mode）」を押すと、作ったダミーの面談（生徒面談とその続き）で、画面 1 から 5 まで通せます。
- **動画**：（提出のときに入れる）
- **なぜ Claude か**
  - **citations**：引用が発話の単位で返るので、原文と完全一致したものだけを画面に出せる。
  - **長い日本語の面談を一度に読める**：話者の無いボイスメモの文字起こしに、話者を付けられる（ダミー 4 本で 370 発話のうち 369 が台本と一致）。
  - **構造化出力と adaptive thinking**：点と行動の候補を、形の決まった出力で受け取り、アプリの側で検査できる。

## 問題

面談（生徒面談・保護者面談・1on1）は、終わった直後に「うまくいった」と感じやすい一方で、言いにくいことを言わなかったこと、相手が自分で決めるまで待たなかったことには、本人が気づきにくい。録音を聞き直す時間はなく、上司が毎回同席することもない。振り返りは「反省の言葉」で終わり、次の面談で何を変えるかが決まらないまま、同じ形の面談が続く。

## なぜ今

- iPhone や Mac のボイスメモで、面談がそのまま文字になるようになった。話者の無い文でも、AI が発話に区切って話者を付けられる。
- 長い文脈を読み、発話の単位で引用を返し、その引用が原文と一致するかをプログラムで確かめられるようになった（Claude の citations）。
- AI の助言は、引用を必須にしても原文と合わないことがある。だから、根拠を検証し、人を採点せず、本人の答えから行動を作る設計が要る。

## Claude がどう解くか

一本の流れは 5 つの画面です。

| # | 画面 | 本人がすること | Claude とアプリがすること |
|---|---|---|---|
| 1 | 面談内容を入力する | 文字起こしを貼る（話者の無いボイスメモの文でよい）。付いた話者と直した所を確かめる | 発話に区切って話者を付け（0a）、聞き違いを直す箇所を挙げ（0b）、意味が通らない箇所の推測を別に添える（0c）。元の文は残す |
| 2 | フィードバックを読む | 先に自分の点と一言を付ける（AI に渡さない）。そのあと読む | 場面を 2 つ（よく表れた所・次に試せる所）。原文のやりとり → 文字起こしから確かめられること → AI の読み（最初は閉じている）→ 問い、の順に出す。項目ごとの点と合計は、その後 |
| 3 | 自分の言葉で | 問いに答えを書く（書かなくても進める） | 待つ（AI を呼ばない） |
| 4 | 次に試すひとつ（Your Spark） | 候補から選ぶ、直して使う、見送る | 「もし（場面）なら、（行動）する」の候補を 2〜3。候補ごとに、本人のどの答えから作ったかを添える |
| 5 | 次の面談で | 続きの面談を貼り、先に「できた／一部／まだ／場面がなかった」と自分の点を付ける | 自己評価を見ずに読み、判定・根拠の引用・なぜの一文・項目ごとの点を返す。本人と AI の判定を並べ、ずれは「確かめる点」として出す |

Claude の使い方（コードで確かめられること）：

- **引用は検証したものだけ**（`engine/citations.mts`）。文字起こしを 1 発話 1 ブロックの document（`source.type: "content"`）にして citations を有効にし、返ってきた `cited_text` が、その発話の文と完全一致したときだけ画面に出す。一字でも違えば捨てる。モデルが本文に「」で書いた言葉は検証していないので、文字起こしに無ければ「」を外して出す（`engine/guard.mts`）。
- **発話の番号を AI に数えさせない**（`engine/utterance-no.mts`）。各ブロックの先頭に札「〔発話 n〕」を書き、文の中ではその番号で発話を指させる。文の中の番号が発話の数の範囲に入っているかも確かめる。
- **引用が要る工程と、形の決まった出力が要る工程を分ける**（`engine/claude.mts`）。citations と構造化出力は同じ呼び出しで使えない（400）。場面・読み・問い（工程 1）と次の面談の判定（工程 4）は citations 付き、整形（工程 0）・点（工程 2）・行動の候補（工程 3）は構造化出力で呼ぶ。
- **整形は 3 つの呼び出しに分ける**（`engine/step0.mts`）。一つの呼び出しに混ぜると、直しが強く働いて、言った言葉まで書き換えるため。0a でモデルが写した本文は、元の文字起こしに当て直す（言葉を変えない）。0c の推測は画面で元の文と並べて見せるだけで、分析には渡さない。
- **先に入った評価を渡さない**（`app/api/*/route.ts`）。分析・候補・次の面談の Route Handler は、本人の自己採点・一言・自己評価、前回の AI の点と判定を受け取らず、入っていれば 400 を返す。
- **点は最後に、合計はアプリが**（`engine/rubric.mts`）。工程 1 には点を書かせず、点は別の呼び出しで項目ごとに出す。合計は判定した項目だけを分母にして 10 点に換算し、「判定しない」を 0 点にしない。**点の尺度（1〜5）と配点は仮**で、画面にもそう書いてある。
- **人物の性質を言い表す言葉を検査する**（`engine/forbidden-words.mts`、`engine/guard.mts`）。AI の出力は欄ごとに検査し、当たった欄は「表示を控えました」に差し替える。画面の文言も同じ一覧で検査する（`app/ui-words.test.mts`）。
- **モデルと呼び方**：既定はすべての工程が `claude-opus-5-5`。adaptive thinking で、考える量は 0a が low、0b・0c が medium、分析が high。system と document にプロンプトキャッシュを付ける。Anthropic SDK はサーバー側（Next.js の Route Handler）からだけ呼び、API キーはブラウザに出さない。

## どこが新しいか

1. **人を採点しない。** 点は面談の点で、人の点ではない。本人が先に自分の点を付け、AI の点は引用と問いの後に置く。
2. **根拠は原文の引用だけ。** 言い換えた引用は捨てる。AI の読みは、原文・確かめられること・解釈に分けて出し、解釈は本人が開くまで閉じておく。「引用は原文と一致」は、読みが合っていることの印ではないと画面に書いてある。
3. **場面では問いで返し、行動は一つに絞る。** 候補は本人の答えから作り、本人が選ぶ・直す・見送る。「もし（場面）なら、（行動）する」の形で、次の面談の文字起こしで確かめられる行動だけ。
4. **次回に戻ってくる。** 前回決めた行動が次の面談でどう現れたかを、引用つきで確かめる。本人の自己評価を先に取り、AI はそれを見ずに読む。
5. **整形を本人が確かめる。** 話者が確かでない発話と、直した所を先に出し、元の文を添える。
6. **（作っている途中）面談する側を覚えている。** 下の「まだ無いもの」。

## 試し方

### Demo Mode（実データ不要）

https://reflectionspark.vercel.app を開きます。

1. 画面 1 で「サンプルを選ぶ（Demo Mode）」→「整形する（発話に区切って話者を付ける）」。「確かめる所」を見て、「確かめた。フィードバックを読む →」。
2. 画面 2 で、自分の点（10 点満点）と一言を入れて「付けた。読む」。場面を読み、「AI の読みを開く」は自分で考えてから押す。「次へ：3. 自分の言葉で →」。
3. 画面 3 で問いに答えを書く（全部に答えなくてよい）。「次へ：次に試すひとつ →」。
4. 画面 4 で候補を読み、「これにする」か「直して使う」か「今回は見送る（持ち帰らない）」。「次へ：次の面談で →」。
5. 画面 5 で「サンプルの続きを選ぶ（Demo Mode）」→「整形する」。自分で「できた／一部／まだ／場面がなかった」と点を選んで「付けた。AI の判定を見る」。

- サンプルは作ったダミーの 1 組で、実在の人物ではありません。
- Demo Mode でも、整形と分析は本物の Claude を呼びます。

待つ時間（公開 URL での実測。2026-11-06、サンプルの 1 組、2 回）：

| 工程 | 1 回目 | 2 回目 |
|---|---|---|
| 整形（1 本目、128 発話） | 63 秒 | 65 秒 |
| 分析（場面・問い・点） | 60 秒 | 59 秒 |
| 行動の候補 | 19 秒 | 18 秒 |
| 整形（続き、83〜84 発話） | 46 秒 | 45 秒 |
| 次の面談の判定 | 45 秒 | 35 秒 |
| 合計 | 3 分 53 秒 | 3 分 43 秒 |

- 本人が読む・書く時間は入っていません。次の面談の判定は、整形が終わるとすぐ裏で読み始めるので、自己評価を付けている間に進みます。
- 待つ間、タブは開いたままにしてください。閉じると、その工程はやり直しになります（貼った文字起こしと、終わった工程の結果は残ります）。失敗したときは、画面の「もう一度〜」のボタンでやり直せます。

環境変数（`.env*` はコミットしない）：

|---|---|---|

何を API に送り、どこに保存するか：

- 送る：貼った文字起こし（4 万字まで）、整形後の発話の並び、場面の種類、「次に試せる所」の場面と本人の問いへの答え（候補を作るとき）、前回の「次に試すひとつ」とできたかの基準（次の面談を読むとき）。
- 送らない：本人の自己採点・一言・自己評価、前回の AI の点と判定、相手の呼び名、工程 0c の推測。
- 保存：このブラウザの localStorage（面談 1 件分）。サーバーには保存しない。
- 実在の人の名前や、本物の面談の文字起こしは入れないでください。

## どう作ったか

- **Claude Code で作った。** AI に何をさせるかの正本は `docs/設計書.md`（採点表の 5 項目、AI の決まり 1〜12、工程ごとに受け取るもの・渡さないもの・返すもの、評価の 12 軸）。プロンプト・コード・テストは、設計書の決まりの番号で書いた（例：テスト名「決まり 1：引用の照合」）。作業の決まりは `CLAUDE.md`。
- **評価を先に作った。** ダミーの台本 12 本を Claude で生成して人が手を入れ、ElevenLabs で音声にし、ボイスメモで文字起こしした（`eval/cases/*/script.txt` と `voicememo.txt`）。文字起こしの聞き違いと抜けは、台本との対応付けで評価に織り込んだ。
- **正解は、AI の出力を見る前に作り手が書いた。** デモで使う 2 本は、そのあと AI の出力と突き合わせて見直した。見直しには、別の会社のモデル（Codex、ChatGPT）の読みも参考にし、決めたのは作り手。
- **数字で決めた。** 工程 0a は、作り方 2 つ × モデル 2 つ × 考える量 2 つを 2 本で測って、既定を決めた（`eval/results/step0-speed/`、`docs/整形の速い作り方.md`）。
- **別のモデルにレビューさせた。** 実装を Codex に読ませ、指摘は再現してから直した。
- **講師を守る約束 4 つ**（引用は原文と一致したものだけ／人を性質で書かない／自己採点を AI に渡さない／点は引用の後）は、テストと Route Handler の作りで守っている。
- 以前に自分で作った試作は、画面の見た目と考え方の参考にした。コードとプロンプトは持ち込まず、期間中に新しく書いた。
